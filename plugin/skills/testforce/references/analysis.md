# 분석 컨텍스트와 소스 기준

1. `context --run <id> --selection <대상>`으로 현재 로컬 코드 컨텍스트를 만든다. Trigger·SOQL에서 직접 찾은 오브젝트 외에 관련 Lookup·부모 등의 Describe가 필요하면 `--objects Parent__c Child__c`처럼 **실제 코드에 존재하는 API 이름**을 명시하여 읽기 전용 컨텍스트를 보강한다. 엔진이 반환한 contextPath 파일을 읽는다. 실제 명령 옵션은 `--help`를 따른다.
2. 클래스, 트리거, 메서드 오버로드, 자연어 기능 설명, Git 커밋·범위·diff 중 사용자 입력을 그대로 보존한다. 후보가 여러 개면 파일·시그니처 목록을 보여주고 선택받는다. 첫 검색 결과를 확정하지 않는다.
3. 현재 소스, 실제 파일 위치, 메서드·분기, 직접 Handler/Service/Batch 호출을 근거로 필요한 시나리오만 추천한다. 최소 개수나 레코드 수 목표는 없다. sourceRefs는 컨텍스트에 존재하는 파일·심볼만 사용한다. 엔진의 구조 검색은 완전한 Apex 의미 분석이 아니다.
4. 커밋은 범위 선택에 사용하며 checkout/reset/deploy하지 않는다. 로컬과 커밋 당시 차이를 구분한다. `source_snapshot_hash`, 커밋, dirty 상태, API 버전을 보존한다.
5. 엔진이 제공한 Describe와 제약 컨텍스트를 읽고 필수값, 타입·길이·정밀도, picklist/record type, lookup, validation/duplicate rule, trigger/flow 조건을 반영한다. 조회 불가능한 규칙은 사실 그대로 알린다. 제약 등급·신뢰도 점수를 만들지 않는다. API 저장과 화면 입력 제약을 구분한다.
6. 실행 전 엔진의 배포본 확인이 실패하면 자동 실행을 진행하지 않는다. 사용자가 정합성을 해결한 뒤 context/확인을 갱신한다. 사용자 소스를 덮어쓰거나 자동 배포하지 않는다.

후보 선택과 추가 목적 확인은 기존 Claude 대화에서 처리할 수 있다. 기본 분석 때문에 브라우저를 열거나 `serve`를 시작하지 않는다. 분석이 끝나면 구조화 초안을 직접 제출하고 패널의 계획 단계에서 새로고침해 검토하도록 안내한다. 패널에 아직 계획이 없다는 사실을 가짜 분석 완료 데이터로 채우지 않는다.

외부 영향: 이메일·callout·후속 비동기·기존 부모 변경 가능성을 코드에서 발견하면 계획의 impact에 표시한다. 범위를 확인할 수 없으면 bounded=false로 남겨 자동 실행을 막는다. 존재하지 않는 범위 제한 인자나 보조 클래스를 제안하지 않는다.
