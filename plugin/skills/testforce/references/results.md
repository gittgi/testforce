# 결과 해석·판정·보존·정리

`status`와 엔진 evidence를 읽는다. 비교 결과는 MATCH(일치), MISMATCH(불일치), UNVERIFIABLE(확인 불가), NOT_EXECUTED(미실행)이다. 빈 assertion, 확보하지 못한 반환값, Job 등록, HTTP 성공만으로 전체 일치를 만들지 않는다. 의도한 오류는 사전 승인한 오류 조건과 비교한다. 준비 실패·조회 실패·비동기 미완료는 업무 결함과 구분한다.

사실에 기반한 차이 설명, 가능한 원인, 추가 확인 제안을 `ai-note`로 별도 제출한다. 가능한 원인은 가설이라고 밝히고 실제 evidenceRefs를 연결한다. 자동 비교 결과를 AI 문장으로 덮어쓰지 않는다. 엔진이 결과를 수집한 뒤 기대값을 바꿔 기존 실행을 통과시키지 않는다.

패널의 **테스트** 목록에서 시나리오 제목을 눌러 목적·방법·기대 결과와 실제 차이를 확인하도록 안내한다. 제목을 누르는 것은 설명 열기이며 재실행이나 선택 변경이 아니다. 기본 화면의 짧은 설명으로 무엇이 일치/불일치/미확인인지 읽을 수 있게 하고, 코드 위치·ID·긴 값·원본 근거는 필요할 때 상세를 연다. 넓은 비교표·증거 상세가 필요할 때만 고급 브라우저를 연다. 원시 JSON은 기본 사용자 답변에 나열하지 않는다. 개발자가 마무리에서 최종 판정(수용/미수용/추가 검토)을 기록하며 이름·날짜 입력은 필요하지 않다. AI가 대신 판정하지 않는다. `reports --run <id>`는 AI 연결 없이도 사실 기반 test-report.md와 test-results.xlsx를 만든다. 보고서의 입력 계획, 실행 직전 baseline, 실행 후 실제값 세 시점이 다름을 유지한다. 검토 전에는 검토 대기다. Fake 결과는 실제 Salesforce 증거가 아니다.

결과 저장 후 **마무리** 단계에서 매번 보존 또는 정리를 사용자가 선택한다. 미선택은 남겨두고 선택 대기다. 보존이면 `keep`; 나중에 열어 정리할 수 있다. 정리이면 `cleanup-preview`의 이번 실행 생성 ID, 현재 상태, 충돌·새 관계·진행 Job을 보여준다. 사용자가 해당 대상을 확인하는 체크와 정리 버튼으로 선택하며 이름·날짜를 다시 묻지 않는다. 같은 대상 해시로 이미 승인한 정리를 단계마다 재승인받지 않는다. **Skill이 Mod bridge/action/token, 브라우저 요청, 자동 TTY 입력으로 판정·보존·정리 선택을 대신해서는 안 된다.** `cleanup`은 승인된 범위만 실행한다. 이름 접두어·넓은 WHERE로 삭제하지 않는다. 기존 참조, 다른 실행, ID 연결 불명 데이터는 삭제하지 않는다. 수동 생성 ID는 명시적 사용자 `confirm-ownership`과 생성 시각·생성자 재조회 전까지 정리 대상으로 인정하지 않는다. 기존 변경 복구는 `restore-preview` → 사용자 `restore-approve` → `restore`, Job 취소는 `cancel-preview` → 사용자 `cancel-approve` → `cancel-job`이다. 이 고급 작업은 브라우저/CLI에서 실제 범위를 검토하는 별도 사용자 승인으로 수행한다.

정리 결과의 성공·실패·남은 ID를 보존하고 보고서를 갱신한다. 정리는 통지·외부 영향·다른 자동화까지 완전히 되돌리는 롤백이 아니다. 완료한 테스트의 재실행은 패널의 새 실행 경로(`rerun`)로 새 run_id를 만들며 이전 증거를 보존하고 다시 검토·승인한다. 결과를 보고 싶어 시나리오를 클릭한 사용자를 재실행 요청으로 해석하지 않는다.
