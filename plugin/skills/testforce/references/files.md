# Excel 편집과 수동 Import

계획 Excel은 검토용, Data Loader CSV는 전송용이다. 둘을 혼용하지 않는다.

이 문서는 선택적 고급 경로다. 기본 `/testforce-ui` 패널의 계획·테스트·마무리에 모든 표와 업로드 입력을 늘어놓지 않는다. 사용자가 파일 편집·수동 Import를 요청할 때만 브라우저 또는 아래 CLI를 사용한다. 그때 필요한 서버를 열 수 있으며 일반 분석 때 `serve`를 자동 시작하지 않는다. JSON 연결 파일이 필요한 부분은 Skill이 작성하고 사용자에게 매번 직접 작성하도록 요구하지 않는다.

## Excel

`excel-export --run <id>`로 생성한 test-plan.xlsx를 제공한다. 사용자가 값·행·기대값을 편집하면 `excel-import --run <id> --file <xlsx>`로 변경 검토를 만든다. 변경점과 엔진의 타입·참조 오류, 빈칸 모호성을 설명한다. 미변경 빈칸은 기존 의미를 보존하며 변경된 빈칸은 기존 요청 유지/필드 생략/null/빈 문자열 중 유효한 의미를 사용자가 고른다. `excel-apply`로 검증한 새 계획을 저장한 뒤 재승인한다. 원본 approved/ID/evidence를 수정해 승인·관찰을 위조하지 않는다.

적용 뒤 패널을 새로고침하면 새 버전과 승인 대기가 반영된다. Mod 동작 토큰이나 브라우저 승인 요청으로 재승인을 대신하지 않는다.

논리키를 안정적으로 유지한다. 행 번호·정렬 순서를 ID로 사용하지 않는다. 새 키·복제·삭제 규칙과 오류는 엔진 검토 결과를 따른다. 수식·매크로·실행 요소를 데이터로 허용하지 않는다. 문자열 정밀도·시간대 손상을 발견하면 원본 값으로 되돌리는 새 계획을 제안한다. CSV 안전 표시와 실제 전송값을 조용히 혼동하지 않는다.

## Data Loader

1. 승인 뒤 `import-generate --run <id> --phase fixture` 또는 `--phase action`을 호출한다. 실제 반환된 파일 묶음과 README만 안내한다. 준비와 동작 파일을 구분한다.
2. 지원 모드·null/빈값 설정은 생성 README와 제품 문서를 따른다. 부모 Import 성공 후 실제 ID를 연결하고 자식 파일을 다시 생성한다. 추적 필드나 오브젝트를 만들지 않는다.
3. 성공·실패 결과를 `import-results`로 각각 수집한다. 안정적인 대응 정보가 부족하면 브라우저의 명시적 ID 연결을 안내한다. 동일 Name이나 원본 행 순서를 근거로 매핑하지 않는다.
4. ID 연결 뒤 엔진이 실제 레코드를 재조회해야 성공 증거가 된다. CSV 생성·완료 버튼·사용자 보고만으로 성공을 기록하지 않는다. 성공/실패/연결 불명확을 분리하여 실패 행만 재개한다.
