# 구현 결정

결정일: 2026-10-15. 일반적인 구현 선택은 별도 사용자 질문 없이 아래와 같이 정했다. 사용자 제품 요구사항과 실제 보안 경계가 우선한다.

1. **TypeScript strict + Node 24 + npm.** 엔진·CLI·파일 처리·서버를 한 런타임으로 운영한다. Python·외부 DB·클라우드 서비스를 필수로 추가하지 않는다. Node/패키지의 실제 버전과 플랫폼 검증은 compatibility 문서에 따로 기록한다.

2. **고급 브라우저는 React/Vite + Fastify.** UI 빌드 후 단일 `serve` 명령이 API와 정적 UI를 제공한다. 기본 사용은 아래의 Mod 중심 결정으로 바뀌었으며 HTTP 서버를 자동 시작하지 않는다. 브라우저 사용 시 기본 포트 0으로 빈 포트를 배정하고 특정 포트 충돌 시 빈 포트로 재시도한다. 별도 모노레포 도구는 추가하지 않았다.

3. **Zod를 공통 런타임 계약으로 사용한다.** 스키마는 JSON Schema로 내보내 Skill이 실제 제출 구조를 확인할 수 있다. 승인 상태는 Plan 밖에 두어 JSON/Excel 초안에서 가져올 수 없다. `eval` 없이 선언적 비교 연산자를 사용한다.

4. **로컬 JSON·증거 파일·배타적 실행 잠금.** 실행 상태는 atomic rename과 fsync, 작업별 잠금으로 보존한다. 대기 중 쓰기의 결과가 저장되지 않으면 UNKNOWN으로 전환한다. 파일 저장소는 같은 OS 계정의 악의적 코드에 대한 보안 격리 제품이 아니다.

5. **현재 소스의 구조 검색과 AI 분석을 분리한다.** 엔진은 실제 파일·메서드·해시·직접 참조를 찾는다. 제한된 구조 검색을 Apex 전체 파서나 커버리지 분석으로 광고하지 않는다. 같은 파일의 오버로드도 정확한 시그니처가 없으면 자동 선택하지 않는다.

6. **SF CLI 기본 연결 + 제한적 공식 REST.** 인증과 승인 Anonymous Apex는 설치된 명령을 사용한다. Describe·Tooling 소스·페이지 쿼리·레코드별 DML은 공식 REST로 구현해 실제 성공/오류를 구조화한다. 모든 CLI 호출은 명시적 target-org와 argv를 사용한다. Salesforce DX MCP는 선택적 읽기 보조이며 쓰기 승인 우회 경로가 아니다.

7. **Fixture와 Update 입력을 모델에서 분리한다.** 준비 레코드의 원래 필드를 Update 값으로 바꾸지 않는다. `fieldOverrides`를 별도 동작 입력으로 검토하고 Excel·CSV·보고서에도 구분해 표시한다. 기존 부모에 대한 간접 변경은 `existingImpactIds`로 계획에 명시한다.

8. **Data Loader는 첫 버전에서 SOAP 모드만 지원한다.** 포함 필드 집합·null 옵션별 CSV를 나누어 생략된 필드가 null Update가 되지 않게 한다. SOAP에서 빈 문자열 의미를 보장할 수 없는 입력은 조용히 변환하지 않고 다른 실행 경로를 안내한다. CSV 하나를 단일 트랜잭션으로 간주하지 않는다. 자세한 계약은 [Excel·Import](excel-import-contract.md)에 있다.

9. **ExcelJS 4.4.0을 제품 런타임으로 사용한다.** 설치 패키지의 MIT 라이선스와 실제 왕복 API를 확인했다. 별도 ZIP 사전 검사가 매크로·외부 링크·수식·압축 폭탄을 차단한다. 열기 전 원본 계획과 대조하고 숨김 시트를 권한 경계로 신뢰하지 않는다.

10. **ExcelJS의 uuid만 11.1.1로 override한다.** 전체 ExcelJS를 오래된 버전으로 내리는 npm audit 자동 수정을 사용하지 않았다. ExcelJS의 CommonJS `v4()` 호출과 uuid 11.1.1 exports를 확인했고 해당 조건부 서식 직렬화 테스트를 통과했다. 적용 후 `npm audit`는 취약점 0건이었다. 이는 향후 취약점 부재를 보증하지 않으므로 배포 시 재검사한다. [공식 보안 공지](https://github.com/advisories/GHSA-w5hq-g745-h8pq).

11. **Import 대응과 생성 소유권을 분리한다.** 전체 반향 입력 필드가 유일하게 일치하거나 사용자가 ID를 연결한 뒤 실제 재조회로 대응을 확인한다. 그 사실만으로 이번 실행이 생성한 레코드라고 승격하지 않는다. 생성 증거가 불충분한 수동 ID는 기본 자동 정리 대상에서 제외한다.

12. **보고서는 AI 없이도 생성한다.** 승인 입력, 실제 재조회 before/after, 비교 결과로 사실 문장을 만든다. 원인 가설·수동 화면 관찰·개발자 판정은 별도다. Fake 결과는 실제 Org 증거가 아님을 표시한다.

13. **Windows 명령 파일은 셸을 거치지 않는다.** 알려진 sf.cmd에서 공식 CLI Node 진입점을 확인하고 Node argv로 실행한다. 알 수 없는 wrapper는 차단한다. 실제 Windows에서 실행하지 않은 검사와 macOS에서의 Windows 경로 계약 검사를 구분한다.

14. **Claude Code Mod를 기본 사용자 화면으로 사용한다.** 2026-10-16 사용자 요청에 따라 이전 읽기 전용 상태 표시에서 세 단계 사용자 흐름으로 바꾼다. 최신 화면 이름은 계획·테스트·마무리다. Mod의 사용자 버튼은 동일 엔진을 호출하며 별도 승인 상태나 Salesforce 쓰기 경로를 만들지 않는다. Skill은 `disable-model-invocation: true`이며 분석·자연어 수정에 집중한다. Mod bridge를 호출해 사용자의 승인·판정·정리 선택을 흉내 내지 않는다. 새 Mod의 최소 버전 호환은 새로 검증한다.

## 2026-10-15 정책 변경

사용자가 Sandbox 전용 제한을 Production 금지로 변경했다. 중앙 org-policy 함수를 엔진과 DML·Apex 어댑터 양쪽에서 적용한다. Sandbox·Developer Edition·Dev Hub 활성 기록으로 확인한 Scratch Org를 허용한다. 이름·URL·로컬 isScratch 플래그는 근거가 아니다. 확인 불가 환경은 계속 차단한다. Org 유형 증거를 계획에 포함하고 변경 시 재승인한다. 기존 live 계획은 최신 컨텍스트로 새로 작성해야 할 수 있다. 실제 데이터 테스트 승인·기존 데이터 보호·정리 정책은 유지한다. 예제의 사용자 요청 배포는 워크벤치의 자동 배포 기능을 추가한 것이 아니다.

## UI·승인 단순화

사용자 피드백에 따라 기본 결과 화면은 승인 입력·실행 전·실행 후·기대값을 표로 비교하고 원시 JSON은 기술 상세로 둔다. 승인은 이름·날짜 입력을 없애고 확인 체크와 버튼 한 번으로 처리한다. 준비와 도구 실행을 기본 승인 범위로 묶어 같은 계획에서 확인을 반복하지 않는다. 로컬 확인 동작과 시각은 서버가 자동 기록하며 실제 Salesforce 수동 실행자와 구분한다. 단순화는 표시와 입력 절차에 적용하며 계획 버전·해시, Org·사용자, 별도 정리 범위, 실제 사용자 경로 검증은 유지한다.

## 2026-10-16 Testforce 패널 중심 흐름

15. **작은 Mod에서 세 단계만 보여준다.** `/testforce`의 자연어 분석과 `/testforce-ui`의 계획 → 테스트 → 마무리를 기본 흐름으로 삼는다. 기본 화면에 원시 JSON이나 모든 고급 기능을 노출하지 않는다. 넓은 표·Excel·수동 Import·결과 불명 조정은 선택적 브라우저/CLI 경로로 유지하여 엔진 기능을 삭제하지 않는다.

16. **필요할 때 Node bridge를 실행한다.** 기본 패널에 HTTP 서버를 요구하지 않는다. Mod가 사용자 동작에 필요한 상태/명령만 같은 엔진으로 전달한다. Skill은 `serve`를 자동 실행하지 않으며 사용자 Mod action·토큰 경로를 호출하지 않는다. 패널의 새로고침은 엔진 상태를 다시 읽고, 자동 패널 열기는 승인·실행을 뜻하지 않는다.

17. **한 번의 개인 설치와 명시적 갱신.** `install-testforce.mjs`가 `/testforce`와 `testforce-panel`을 개인 Claude 설정에 등록한다. Node 24와 엔진 경로는 설치된 Mod 쪽에 두고 업무 workspace·Claude 권한 설정을 변경하지 않는다. 소유가 확인된 설치만 `--update`로 갱신하고 다른 동명 파일은 보존한다. 소스 Plugin 방식은 `configure-mod.mjs`와 `--plugin-dir`로 계속 지원한다.

## 시나리오 설명과 테스트 시작 단순화

18. **한 화면에 모든 기술 정보를 펼치지 않는다.** 사용자 피드백에 따라 기본 화면은 제목·선택·상태 목록으로 줄인다. 제목을 클릭하면 무엇을 확인하는지, 어떤 조건에서 어떤 동작을 하는지, 기대 결과가 무엇인지 설명한다. 테스트 결과를 확인할 때도 해당 설명을 열 수 있다. ID·코드 위치·스크립트·긴 값은 별도 상세로 접어두되 승인 검토에서 접근 가능하게 유지한다.

19. **제목 열기와 실행 대상 선택을 분리한다.** 제목 클릭은 상세를 여는 UI 상태이고, 체크는 계획의 실행 대상 변경이다. 보기만 했는데 계획이 바뀌거나 다시 승인해야 하는 동작을 만들지 않는다. 한 항목을 열었다고 그 항목만 실행한다고 표시하지 않는다.

20. **테스트 시작 한 버튼으로 기존 단계를 연결한다.** 승인한 선택 묶음에 대한 준비·도구 실행·수집을 `run-tests`가 순서대로 호출한다. 실제 실행은 사용자가 패널 버튼으로 시작하며 Claude에게 다시 실행을 부탁하게 하지 않는다. 사람 실행은 대기로 남고 비동기 완료의 긴 관찰은 별도다. 준비 실패·UNKNOWN·중단·완료 상태를 성공으로 바꾸거나 원격 쓰기를 자동 반복하지 않는다. 완료된 테스트는 새 실행으로 시작하고 이전 증거를 보존한다. 단계를 한 버튼에 연결하는 것은 하나의 Salesforce 트랜잭션이나 롤백을 제공한다는 뜻이 아니다.
