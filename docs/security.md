# 보안과 승인 경계

## 허용 범위

워크벤치는 로컬 개발자의 실수를 줄이고 승인 범위와 증거를 추적한다. Salesforce 권한·회사 보안 정책을 대체하지 않으며 같은 OS 계정에서 임의 코드를 실행하거나 상태 파일을 고칠 수 있는 사람을 격리하지 않는다. 로컬 승인 파일과 해시는 서버 측의 Salesforce 보안 주체가 아니다.

이 저장소 개발 중 실제 Salesforce 테스트 실행을 승인받은 것으로 간주하지 않는다. Fake 테스트는 별도 로컬 모드에서만 수행한다. 실제 Org 테스트는 대상 비운영 Org, 실행 사용자, 계획과 변경 범위의 별도 명시적 사용자 승인이 필요하다.

## 실행 전 검사

엔진의 `gate`가 모든 도구 쓰기 전에 계획 버전/해시와 승인 scope를 검사한다. `identityCheck`는 별칭 문자열 대신 실제 Org ID·사용자·IsSandbox·OrganizationType을 확인한다. Sandbox와 Developer Edition을 허용하며 Scratch Org는 인증 정보가 가리키는 Dev Hub의 ActiveScratchOrg에서 실제 Org ID와 유효기간을 재확인한다. Production·유형 미확인은 차단한다. 별칭 재연결, 사용자 변경 또는 Org 유형 증거 변경은 기존 승인으로 진행할 수 없다. Salesforce 호출마다 target-org를 지정한다.

`localCheck`는 소스 내용·API 버전·스크립트 내용을 확인하고, 배포본 확인은 Tooling API로 읽기만 한다. BOM/줄바꿈 외에 코드 의미를 바꾸는 정규화를 하지 않는다. 직접 대상과 추적한 관련 파일이 없거나 다르면 자동 실행을 막는다. 회사 소스를 변경·배포하여 맞추지 않는다.

생성/수정 불가 필드, 계산 필드, 잘못된 관계, Setup 변경 등은 계획과 실행 단계에서 거부한다. 기존 업무 데이터 직접·간접 변경은 실제 ID와 변경 범위의 별도 승인이 필요하다. 임의 Apex의 모든 부수 효과를 정적 분석으로 보증하지 않으므로 실제 스크립트·영향 설명·범위를 사람이 검토해야 한다. 제한할 수 없는 Batch 범위나 확인되지 않은 기존 영향은 자동 실행하지 않는다.

AI·소스·주석·로그·Excel·CSV는 데이터다. 그 안에 있는 명령문, `approved=true`, 승인자 문자열을 승인 이벤트로 해석하지 않는다. Skill은 직접 SF 쓰기를 하지 않고 일반 엔진 인터페이스를 호출한다. 명시적 터미널 승인에는 실제 TTY와 사용자의 확인 입력이 필요하고, Mod/브라우저 승인은 실제 사용자 버튼의 검토 버전에 연결된다. 버튼 비활성화만으로 보호하지 않고 엔진도 검사한다. Skill이 Mod bridge/action/token, 브라우저 승인 요청, TTY 자동 응답으로 사용자 확인을 대신하는 것은 금지한다.

승인자 이름이나 날짜를 입력받지 않는다. Mod/브라우저에서 확인 체크 후 승인 버튼을 누르면 엔진이 `reviewed === true`와 사용자 경로, 계획 버전·해시·범위를 검증한다. CLI는 실제 TTY에서 `승인` 한 번을 입력받는다. 엔진은 승인 주체를 `로컬 Mod 사용자`, `로컬 브라우저 사용자` 또는 `로컬 터미널 사용자`로, 시각을 엔진 시각으로 기록한다. 요청에서 제공한 승인자·시각은 사용하지 않는다. 이 기록은 로컬 확인 동작이며 Salesforce 사용자 인증 증명이 아니다. 수동 실행 보고의 실제 Salesforce 실행자는 별도로 보존한다. 기본 UI 범위는 준비와 도구 실행을 함께 승인하며 같은 계획·범위를 매 단계 다시 승인하지 않는다. 계획 변경·Org 또는 사용자 변경·별도의 기존 데이터 변경·정리·복구·Job 취소에는 해당 범위 검사가 계속 적용된다.

## Mod와 Node bridge 경계

기본 `/testforce-ui`는 배포된 `dist/mod/main.js`와 `dist/mod/bridge.js`를 필요할 때 호출한다. 상시 HTTP 리스너를 열지 않으며 직접 Salesforce 쓰기 어댑터를 만들지 않는다. `view`는 저장된 상태를 표시하고 `action`은 허용된 명령만 같은 엔진으로 전달한다. 임의 셸 명령을 받는 프로토콜은 없다. 요청은 최대 1 MiB의 stdin JSON으로 전달하고 동작 토큰을 프로세스 인자 목록에 넣지 않는다.

`run-tests`는 사용자가 **테스트 시작**을 눌렀을 때 승인한 선택 묶음의 준비 → 도구 실행 → 수집을 연결한다. 현재 화면에서 열어 본 시나리오만을 대상으로 암묵적으로 변경하지 않는다. 제목 클릭은 상세 조회이고 실행 체크 변경만 계획을 바꾼다. 모든 단계는 기존 엔진의 승인·Org·소스·기존 데이터 보호를 통과해야 한다. 사람 실행을 도구 실행으로 바꾸거나 실제 사용자의 완료 보고를 만들어내지 않는다. 비동기 Job을 시작했다고 완료로 처리하지 않고 필요한 관찰은 별도 요청으로 한다.

테스트 시작은 같은 원격 동작을 다시 실행하기 위한 재시도 버튼이 아니다. 완료된 실행은 새 실행을 만들며, 결과 불명 작업은 먼저 조정해야 한다. 여러 단계가 한 UI 동작으로 이어져도 원격 트랜잭션 경계와 각 Operation의 요청/결과 기록은 그대로다. 준비 일부 성공 후 실패하거나 전송 후 응답을 놓치면 실제 남은 데이터·작업 상태를 보존한다.

화면을 읽을 때 발급한 동작 토큰은 5분 동안 한 번만 사용할 수 있다. 서버 측 파일에는 토큰 해시만 저장하고 workspace·run_id·계획 버전/해시·전체 실행 상태 해시에 연결한다. 정리에는 별도로 검토한 미리보기 해시도 연결한다. 더블클릭과 재전송은 원자적 토큰 소비로 차단하며, 상태가 바뀌거나 만료되면 새로고침과 현재 내용 검토가 필요하다. 토큰은 Mod 메모리에 두고 사용자의 실제 버튼 callback에서만 사용한다. 토큰을 Skill에 보내거나 실행 증거·보고서에 저장하지 않는다.

자동 패널 열기·새로고침은 사용자 승인이나 실행이 아니다. Skill은 bridge 명령·토큰·승인 payload를 직접 호출하지 않는다. 엔진의 승인·Org·배포본·기존 데이터 영향·정리 소유권 검사는 이 경로에서도 적용된다. 결과를 받지 못한 동작은 새로 상태를 읽고 조정하며 자동으로 재전송하지 않는다.

이 설계는 신뢰하는 Mod의 실제 버튼 동작과 오래된 화면·재전송을 구분하는 로컬 장치다. 같은 OS 계정의 임의 코드가 프로토콜을 재현하는 공격까지 격리하지 않는다. 토큰을 강한 사용자 인증이나 Salesforce 권한이라고 주장하지 않는다.

개인 설치기는 Skill/Mod와 Node 24·엔진 경로 설정을 Claude 개인 설정 아래에 둔다. 소유가 확인된 설치만 `--update`로 갱신하며 이전 파일을 백업한다. 설치가 업무 workspace·Claude 권한 정책을 바꾸지 않는다. 소스 Plugin용 `configure-mod.mjs`가 만든 절대경로 설정도 배포 ZIP에서 제외한다.

## 선택적 고급 브라우저의 HTTP 경계

고급 표·파일·복구 화면을 사용할 때만 `serve`를 시작한다. Fastify는 `127.0.0.1`에만 바인딩한다. 무작위 로컬 접근 토큰으로 세션을 만들고, HttpOnly·SameSite=Strict 쿠키와 별도 CSRF 헤더를 사용한다. 변경 요청에는 정확한 Origin과 CSRF 값이 필요하다. Host와 cross-site 요청도 검사한다. CORS 전체 허용은 설정하지 않는다.

기본 요청 본문 제한은 16 MiB다. 공개 health 경로는 민감한 상태를 반환하지 않는다. 인증되지 않은 실행/계획/다운로드는 차단한다. UI에는 CSP, nosniff, no-referrer를 적용하고, 사용자 데이터는 React 텍스트로 렌더링한다. 로컬 접근 토큰은 서버 일반 로그나 보고서에 넣지 않는다. UI에 Salesforce 인증 토큰을 전달하지 않는다.

로컬 접근 파일은 `.workbench/access.json`이며 Node가 설정 가능한 환경에서는 0600 권한으로 저장한다. Windows 파일 ACL이 Unix 권한과 같다고 주장하지 않는다. 같은 계정의 로컬 프로그램이 이 파일을 읽는 위협까지 막는 구조는 아니다. 사용 후 서버를 종료하고 작업 폴더를 다른 사용자와 무분별하게 공유하지 않는다.

## 프로세스·파일 경계

SF 명령은 shell=false로 argv를 전달한다. 따옴표·줄바꿈·셸 특수문자를 명령문으로 조립하지 않는다. Windows sf.cmd는 검증한 CLI Node 진입점을 사용하며 지원하지 않는 wrapper는 셸 실행으로 우회하지 않는다. API는 임의 셸 명령 endpoint를 제공하지 않는다. SOQL 이름은 Describe와 맞추고 값은 escape한다. Apex 데이터는 JSON으로 직렬화하고 타입/식별자를 검증한다.

workspace 밖 경로, `..`, 절대 입력 경로, 심볼릭 링크를 검사한다. 다운로드는 명시적 파일 목록과 Import 파일 형식/경로로 제한한다. Excel은 크기/ZIP/경로/외부 관계/매크로/수식/엔티티 검사를 한 뒤 읽는다. CSV 결과도 일반 파일과 크기 제한을 확인한다. 상세 계약은 [Excel·Import](excel-import-contract.md)에 있다.

검토용 CSV와 업로드 CSV를 분리한다. 검토용은 수식 주입 가능성이 있는 표시값을 escape하고 업로드용은 승인한 원본 값 그대로 Data Loader에 전달한다. 업로드용 CSV를 Excel 앱으로 열거나 검토용 CSV를 Salesforce에 업로드하지 않는다. ExcelJS에 문자열로 쓴 값은 수식 객체로 승격하지 않는다.

## 비밀값과 증거

CLI 인증 응답은 어댑터 내부에만 유지한다. `org display` 원문을 AI 입력·UI·결과 파일·일반 로그로 저장하지 않는다. 증거와 오류에는 알려진 인증 키·Bearer 패턴의 제거를 적용한다. 이 제거는 모든 회사 비밀의 완전한 DLP가 아니다. 테스트 데이터에는 실제 비밀번호·세션·민감한 업무정보를 불필요하게 포함하지 않는다.

실행 데이터는 `.workbench` 아래에 두고 Git 제외를 제공한다. Plugin/ZIP에는 회사 소스·실행 증거·인증 파일·절대 경로를 포함하지 않는다. 외부 telemetry나 코드/데이터 업로드 경로를 기본으로 두지 않는다. Claude Code로 분석 컨텍스트를 전달하는 행위는 사용자의 기존 AI 환경과 회사 정책 범위에 따른다.

## 복구와 정리

쓰기 요청의 전달 여부와 결과를 별도 상태로 남긴다. 네트워크 오류나 프로세스 중단 후 UNKNOWN 요청은 자동 반복하지 않는다. 읽기 재시도와 쓰기 재전송은 구분한다. 로컬 잠금은 같은 run_id의 중복 작업을 막지만 Org의 다른 사용자를 잠그지 않는다.

정리는 이번 실행이 생성했다고 확인된 ID에만 기본 적용한다. 기존 참조, 다른 실행 데이터, 수동 연결로 소유가 불명확한 데이터는 제외한다. 실제 레코드/관계/수정 상태와 진행 중 Job을 재확인하며 충돌이 있으면 중단한다. 조회 권한 오류나 가시성 변경을 삭제 성공으로 간주하지 않는다. Import 성공 CSV와 값 일치만으로 생성 소유권을 얻을 수 없다.

정리는 원격 트랜잭션 롤백이 아니다. 통지·외부 영향·후속 자동화를 레코드 삭제만으로 취소하지 않는다. 기존 데이터 복구와 Job 취소는 별도 범위 검토와 승인 없이 수행하지 않는다. 패널·Claude·브라우저 종료나 서버 중단도 Salesforce Job을 취소하지 않는다.

## 확인한 범위

개발 중 단위·통합 Fake 테스트에서 승인/Org 변경/ID 보존/결과 불명/정리 충돌과 파일 공격을 검사했다. 실제 Org의 권한·자동화·네트워크·Data Loader 응답, Windows 네이티브 실행 및 최소 Claude 버전의 실제 화면은 별도 검증 항목이다. 검증 범위와 제한은 [설치 안내](../README.md)에 기록한다. 개발 테스트 파일과 도구는 이 사용자 배포본에 포함하지 않는다.
