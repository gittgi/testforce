# 제품 요구사항 기준

기준일: 2026-10-16. 최초 「Salesforce Sandbox 테스트 워크벤치」 요청과 이후 비운영 Org 정책·승인 간소화·Testforce Mod 중심 UX 요청을 제품 기준으로 삼는다. 아래 최신 UI 역할은 최초의 읽기 전용 Mod 제한을 대체하며 엔진 안전 규칙은 유지한다. 구현·검증 상태는 [수용 기준](acceptance-matrix.md)와 [진행 상태](status.md)에 기록한다. 이 문서는 기능을 다음 버전으로 미루는 합의가 아니다.

## 목적과 책임

Testforce는 기존 Claude Code 세션에서 로컬 Salesforce 코드를 분석하고 승인된 비운영 Org 데이터의 준비·실행·비교를 지원하는 로컬 개발 도구다. Apex Test Class, 배포 검증, 커버리지 도구를 대체하지 않는다. 일치 결과는 승인한 비교 조건의 일치를 뜻하며 업무 요구사항 전체의 정확성을 보증하지 않는다.

개발자는 시나리오·기대값·변경 범위·실행 경로를 검토하고 승인하며 최종 판정과 정리를 선택한다. `/testforce` Skill은 실제 소스에 근거한 분석·추천·구조화 초안·자연어 편집·원인 가설을 담당한다. `/testforce-ui` Mod가 계획·테스트·마무리의 기본 화면이며 필요할 때 Node bridge로 동일 엔진을 호출한다. 시나리오 제목은 설명을 열고 별도 체크로 실행 대상을 정한다. 사용자가 테스트 시작 버튼으로 승인한 선택 묶음의 준비·도구 실행·수집을 진행한다. 엔진은 권한 경계, 실제 Org 확인, 계획 버전, 데이터 작업, 증거, 비교, 재개, 파일을 담당한다. React UI는 큰 표·파일·복구 등 선택적 고급 경로다.

핵심 흐름은 로컬 코드 선택 → Claude Code 분석 → 시나리오 선택·추가 → 데이터·기대값 검토 → 버전별 승인 → 준비 → 사람 또는 도구 실행 → 실제값 수집·비교 → 개발자 판정 → MD/Excel → 보존 또는 정리다.

## 첫 버전 기능 범위

| 영역 | 제품 계약 |
| --- | --- |
| 대상 입력 | 클래스, 트리거, 정확한 메서드 시그니처, 기능 설명, 커밋/범위/diff를 지원한다. 여러 packageDirectory를 읽고 모호한 후보를 자동 확정하지 않는다. |
| 분석 기준 | 현재 로컬 소스를 사용한다. Git 입력은 범위를 좁히며 checkout·reset·배포를 하지 않는다. 파일·해시·API 버전·커밋·dirty 상태를 기록한다. |
| AI 연결 | run_id/request_id/plan_version/source_snapshot_hash가 일치하는 구조화 응답만 제출받는다. 브라우저는 실제 Claude 응답 대기 상태를 표시한다. 별도 AI API 키나 클라우드 서버를 요구하지 않는다. |
| 시나리오 | 근거·실제 소스 위치·전제조건·동작·기대값을 갖는다. 복수 선택, 직접 추가, 편집, 일괄/개별 실행 방식 선택을 지원한다. 의미 없는 최소 개수를 만들지 않는다. |
| 준비 모델 | Fixture, 재조회 Baseline, Action, Expectation을 분리한다. Insert Trigger의 대상 Insert는 Action이다. Update 준비값과 fieldOverrides의 변경값은 별개다. |
| 제약 | Describe, RecordType/Picklist/Lookup, 활성 규칙·자동화의 조회 가능한 정보를 최대한 반영한다. 화면 입력 제약과 API 저장 제약의 차이를 설명한다. 의도한 오류 입력은 보정하지 않는다. |
| 승인 | 실제 Org/사용자, 소스/배포본, 데이터, 기대값, DML·스크립트, 영향 범위, 관찰 조건을 버전·해시에 연결한다. 준비 승인과 도구 실행 승인을 구분한다. |
| 공유 Sandbox | 최신 사용자 요청(2026-10-15)에 따라 Production 쓰기만 금지하는 비운영 정책으로 변경했다. 공식 조회로 Sandbox·Developer Edition·활성 Scratch Org를 확인하면 허용하며 유형 미확인은 거부한다. 기존 데이터 직접/간접 변경은 실제 ID와 영향의 별도 승인을 요구한다. Setup 데이터는 조회·참조가 기본이다. |
| Trigger | 실제 Insert/Update/Delete로 실행하고 allOrNone·부분 성공·요청 단위를 기록한다. 여러 요청을 단일 Bulk 트랜잭션이라고 표시하지 않는다. |
| Service | 기존 public/global 진입점, static/instance, 생성자/인자를 지원한다. 상관 ID 구조 로그로 반환을 검증하고 누락·잘림·중복을 성공으로 추정하지 않는다. |
| Batch | 실제 executeBatch와 Job ID, start 범위·scope·후속 비동기 관찰을 사용한다. 실행 직전 승인 대상 범위를 재확인한다. 등록·완료·업무 결과를 구분한다. |
| 사람 실행 | 화면 저장, Data Loader Import, 승인 Anonymous 스크립트의 절차·입력·관찰을 제공한다. 완료 보고와 DB 증거를 구분하고 실제 사용자·시각·경로를 남긴다. |
| Excel | 생성 양식의 값·행·기대값 편집, 재불러오기, 변경점·빈칸 의미 확정, 타입/참조 검증, 재승인을 실제로 지원한다. 행 위치로 대응하지 않는다. |
| Import | 준비/동작 CSV 분리, 부모→ID 연결→자식 순서, 성공/실패 파일, 유일한 대응 또는 명시적 ID 연결을 지원한다. 실제 조회 전 성공·소유권을 추정하지 않는다. |
| 비교 | 선언적 비교만 사용한다. MATCH/MISMATCH/UNVERIFIABLE/NOT_EXECUTED를 한국어로 표시한다. 숫자·날짜·오류·Job·존재/건수·변경을 다룬다. 빈 검사는 자동 일치가 아니다. |
| 결과 | test-plan.xlsx, test-results.xlsx, test-report.md, plan/state/binding/operation/evidence/import 자료를 저장한다. 세 시점·AI 의견·개발자 판정을 분리한다. |
| 복구 | 쓰기 전 의도와 전송 상태를 저장하고 결과 불명을 자동 재전송하지 않는다. 중단/재개와 새 run_id 재실행을 구분한다. 중복 프로세스·더블클릭을 막는다. |
| 정리 | 매 실행에서 보존 또는 정리를 선택한다. 이번 실행 생성 ID만 기본 대상이며 현재 상태·관계·비동기·충돌·부분 실패를 확인한다. 기존값 복구와 Job 취소는 별도 승인 작업이다. |
| UI/CLI | 기본 작은 Mod는 계획·테스트·마무리 세 단계다. 짧은 목록에서 시나리오 제목을 눌러 쉬운 설명·결과를 읽고, 별도 체크와 테스트 시작 버튼으로 선택·실행한다. 한국어 고급 브라우저와 Windows 중심 CLI도 제공한다. 모든 버튼은 동일 엔진에 연결하고 새로고침 이후에도 상태를 유지한다. 원시 JSON을 기본 사용자 입력으로 요구하지 않는다. |
| Plugin/Mod | `/testforce` Skill과 `/testforce-ui` Mod를 공식 형식으로 제공한다. 개인 설치와 소스 Plugin을 지원한다. 기본 사용에는 HTTP 서버가 필요 없고, Skill은 serve나 Mod bridge/action/token을 자동 호출하지 않는다. Mod 불가 시 브라우저/CLI로 같은 기능을 사용한다. |
| 보안 | loopback, 접근 인증, Host/Origin/CSRF, 파일 크기·경로·심볼릭 링크·Excel 실행 요소 검사, 비밀값 제거를 적용한다. 임의 셸 endpoint를 제공하지 않는다. |
| 검증 | Fake로 단위·통합·E2E를 실제 실행한다. 실제 Sandbox, Windows, Claude Mod 최소 버전은 각각 별도 검증 여부를 기록한다. |

## 제외 범위와 개발 권한

운영 Org 쓰기, 사용자 소스 변경, 코드 자동 배포, 접근 제한자 변경, 추적 메타데이터 생성, 규칙/자동화/권한/공유/로깅 설정 변경, Salesforce 화면 RPA, 별도 AI 챗봇, 외부 DB, 범용 ETL, 특정 업무에 종속된 기능은 구현 범위가 아니다.

이 개발 요청은 로컬 소스·의존성·빌드·테스트를 허용한다. 인증된 Org의 임의 fixture 생성이나 실제 업무 테스트를 허용하지 않는다. 실제 Org 테스트는 대상·계획·변경 범위에 대한 별도 명시적 승인을 받은 뒤 수행한다. Fake 승인 이벤트로 live 실행 권한을 만드는 테스트를 하지 않는다. 전역 권한·회사 보안 정책·PowerShell 실행 정책·Claude 권한을 완화하지 않는다. push·배포·공개·외부 업로드는 하지 않는다.

실제 환경 제한 때문에 사용할 수 없는 경로는 차단 사유와 대안을 표시한다. 미검증 환경을 검증 완료로 보고하지 않으며, 미구현 항목은 [수용 기준](acceptance-matrix.md)에 드러낸다.

## 간단한 사용자 경험의 수용 조건

- 개인 설치 후 실제 Salesforce 소스 폴더에서 Claude를 시작해 `/testforce`와 `/testforce-ui`로 진행한다. 이미 열린 패널은 재호출하지 않으며 계획 변경 후 새로고침할 수 있다.
- 계획 승인·결과 판정·정리 선택은 사용자가 직접 한다. 승인자 이름·날짜나 JSON 작성은 기본 사용에 필요하지 않다.
- Skill은 일반 엔진 분석·계획 인터페이스만 사용하며 사용자용 Mod bridge/action/token·브라우저 승인 요청·TTY 자동 입력으로 승인을 대신하지 않는다.
- 작은 패널 때문에 Excel·수동 Import·UNKNOWN 복구나 승인·Org·배포본·소유권 검사를 없애지 않는다. 고급 경로를 필요할 때 제공한다.
- Node 24·엔진 위치 설정은 설치된 Mod 쪽에 두고 업무 workspace를 설치 설정으로 변경하지 않는다. 최소 버전과 새 Mod의 실제 실행 결과는 이전 Mod 검증과 별도로 기록한다.
- 시나리오를 클릭하면 검증 목적·조건·실행 방법·기대 결과를 읽고 테스트 화면에서도 실제 결과와 함께 확인한다. 코드·ID·스크립트는 접힌 상세에서 접근 가능하다. 제목을 보는 동작은 선택 변경이나 실행 요청이 아니다.
- 테스트 시작은 승인한 선택 묶음의 준비·도구 실행·수집이다. 사람 실행을 대신하지 않고 비동기 완료의 긴 관찰을 자동으로 붙이지 않는다. 완료된 테스트는 새 실행으로 시작한다. 실행을 위해 Claude에게 다시 명령하도록 안내하지 않는다.
